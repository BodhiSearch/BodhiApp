# 202607 Plans — Index

Plans and fix briefs from July 2026 onward (later one-off plans also land here).

Each entry: date added (YYYY-MM-DD) — file — summary. Dates are git creation dates (renames followed); they are not updated on edit. See [../CLAUDE.md](../CLAUDE.md) for maintenance rules.

- 2026-07-01 — [20260701-oauth-single-step-flow.md](20260701-oauth-single-step-flow.md) — Implementation plan to collapse the 3rd-party app OAuth access-request flow from a two-step round-trip into a single hop, where the app builds the full Keycloak authorize URL itself and the Bodhi review page redirects straight to Keycloak on approve. Covers backend contract changes, the review-page frontend, the in-repo test-oauth-app, and full E2E across redirect and popup flows.
- 2026-07-02 — [this-is-too-old-crystalline-sloth.md](this-is-too-old-crystalline-sloth.md) — Fix plan for a migration-governance bug caused by the single-step OAuth flow work: it edited an already-shipped migration in place instead of adding a new one, breaking deployed DBs with a NOT NULL constraint failure. Reverts migration 000009 to its original shipped form and adds a new migration 000026 to drop the flow_type/redirect_uri columns instead.
- 2026-07-04 — [we-need-to-have-velvet-eclipse.md](we-need-to-have-velvet-eclipse.md) — Implementation plan adding a per-resource access: boolean to the /bodhi/v1/mcps and /bodhi/v1/models list responses so callers can tell which listed MCPs/models they can actually invoke versus merely see, reusing the existing AccessPolicy grant predicates. Details backend DTO/handler changes across services and routes_app, OpenAPI regen, frontend fixture updates, and a full grant-combination test matrix at every layer including E2E.
- 2026-07-05 — [next-we-want-to-delegated-church.md](next-we-want-to-delegated-church.md) — Implementation plan for an OAuth access-request 'exchange/upgrade' flow letting an app with an existing approved grant request more permissions with the review form preselected from its prior grant, scoped to preselect plumbing only (no token invalidation this iteration). Covers a new source_access_request_id column, optional-auth request-access route, review-response embedding of the previous grant, frontend preselect mapping, bodhi-js SDK changes, and tests across all layers, with deferred hardening logged to nicetohave.md.
- 2026-07-17 — [want-to-change-the-synchronous-engelbart.md](want-to-change-the-synchronous-engelbart.md) — Implementation plan for a hard (non-backwards-compatible) migration of the BodhiApp API token format to sk-bodhiapp_ with an appended CRC32 checksum, enabling GitHub secret-scanning detection and offline format validation before any DB lookup. Covers shared format constants, generation/validation code changes, doc/OpenAPI updates, and tests across Rust, frontend, and E2E layers.
- 2026-07-19 — [we-have-an-issue-toasty-donut.md](we-have-an-issue-toasty-donut.md) — Implementation plan to make the review_url returned by the app-access-request endpoint origin-aware, reflecting the actual Host header the request arrived on (validated against loopback hosts/server IP) instead of a static public_server_url that resolves to browser-hostile 0.0.0.0 on local installs. Mirrors existing setup-flow host-detection logic into a new SettingService::resolve_public_server_url method, with changes to services/routes_app and tests at each layer.
- 2026-07-22 — [the-following-is-broken-declarative-dream.md](the-following-is-broken-declarative-dream.md) — Bug-fix plan for a broken MCP OAuth reconnect flow (e.g. reconnecting Exa), diagnosing three compounding defects: a trailing-slash URL corruption on OAuth callback redirect, a backend update that deletes the very token it's about to link, and a frontend edit-load bug that conflates auth_config_id with the real oauth_token_id. Details fixes in the callback route, mcp_repository.rs, and mcpFormStore.ts, plus regression tests at backend and frontend layers.
- 2026-08-01 — [share-plan-to-fix-adaptive-newell.md](share-plan-to-fix-adaptive-newell.md) — Implementation plan to fix the weak PBKDF2 (1,000-iteration) database encryption key derivation used for BODHI_ENCRYPTION_KEY, introducing a two-tier KEK+HKDF scheme with a versioned `v2:` ciphertext prefix, a migration pass for the `tenants` table, and a new legacy-ciphertext error for all other encrypted columns. Covers the settled design decisions, phased Rust implementation across services/lib_bodhiserver, fixture/tooling key updates, and full verification steps.
- 2026-08-22 — [prepare-plan-for-implementation-drifting-conway.md](prepare-plan-for-implementation-drifting-conway.md) — Multi-phase implementation plan to replace BodhiApp's bespoke third-party app authorization flow with a standard OAuth-aligned flow: a single `/ui/apps/auth/` consent route, a stateless Keycloak protocol mapper, and removal of the Keycloak-side access-request record and open-redirect risk. Spans keycloak-bodhi-ext and BodhiApp (services, routes_app, frontend, test-oauth-app, and E2E), with strict phase/deploy sequencing and rollback notes.
- 2026-08-24 — [we-are-launching-a-temporal-snail.md](we-are-launching-a-temporal-snail.md) — Implementation plan for a temporary marketing redirect page at getbodhi.app/tools/free-billion-tokens-bodhi-app/ that forwards visitors to the free-tier LLM API model-router design-partner Tally interest form, using a static noindex HTML stub with client-side redirect plus meta-refresh fallback (since the GitHub Pages static export can't do a true 302). - 2026-08-24 — [prompt-simplify-compliant-oauth-apps-flow.md](prompt-simplify-compliant-oauth-apps-flow.md) — Kickoff prompt for a fresh BodhiApp session to implement the BodhiApp half of the OAuth-aligned third-party app authorization flow, after keycloak-bodhi-ext landed its half.
