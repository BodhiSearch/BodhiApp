- 2026-09-18 — [remote-access-info-discovery.md](remote-access-info-discovery.md) — Follow-up to the Remote Access feature: advertise public reachability on the anonymous `/bodhi/v1/info` so a third-party app's **backend** can discover the user's public base URL (today only Chrome Local Network Access reaches the instance, which is browser-only). Adds `url_public` (from a new env-only `BODHI_PUBLIC_URL_REACHABLE`, absent ⇒ false) and an optional `remote_access[]` tunnel summary collapsed to coarse enums. Built around one constraint — the endpoint is anonymous and becomes internet-reachable through the tunnel, so it must never call `TunnelService::status()`, which spawns a subprocess and hits the Cloudflare API. Adversarial review of the first draft found two blockers now folded in: readiness never self-healed (only the admin page refreshed it), and `dns_conflict` mapped two different ways.
